# L1 历史 ST 最小修复草案（未应用正式源码）

## 已可独立实施的窄修复

1. 在 `microcap_top100_mom16_biweekly_live_v2_0.py` 的嵌入频率模块 `is_st_name` 中，把证券简称标准化为去空格大写后，用锚定前缀 `^(?:[SG])?\*?(?:ST|PT)` 判 ST/PT。覆盖旧 `S ST`、`S*ST`、`G ST`、`G*ST`，同时保留原 `ST`、`*ST`、`PT`。先对更名源的旧/新名称做全量反例；不要用目标表 `name` 列投射历史状态。
2. 在嵌入基础模块及独立 `microcap_top100_mom16_biweekly_live.py` 的 `is_live_tradable_name` 使用同一谓词，确保当前发布门槛也拒绝这些前缀。`is_tradable_name` 目前只负责“退/退市/摘牌”名称，不宜隐式改变其非 ST 调用语义。
3. 源码的最小判定形状：

   ```python
   def is_st_name(name: str | None) -> bool:
       normalized = re.sub(r"\s+", "", str(name or "").upper())
       return re.match(r"^(?:[SG])?\*?(?:ST|PT)", normalized) is not None

   def is_live_tradable_name(name: str) -> bool:
       return is_tradable_name(name) and not is_st_name(name)
   ```

   对 v2 嵌入模块要确认 `is_st_name` 的同一函数对象可从基础模块访问；若不能，提取共同纯函数并在两个执行入口实际加载后做等价断言。

## 需要完整事件证据才能实施的历史修复

现行 `build_st_intervals_from_notices` 不宜只补几个标题关键词，因为状态机还有两个独立错误：

- “为/申请/争取撤销”的进展标题被当作已撤销；“撤销退市风险警示并实施其他特别处理”被当作彻底退出。`002102` 的月度进展公告可错误地把 2010—2023 串为 ST；`002207` 的 2020-06-16 申请公告可导致 2011—2013 的 25 行被反推为 ST。
- `600180` 的 2011-12-14 《关于公司撤销退市风险警示的公告》标题单看像退出，但官方正文明确自 2011-12-15 **实施其他特别处理**，简称 `*ST 九发` 改为 `ST 九发`；属于 ST 内部降级而非 ST→非 ST。正文 `https://static.cninfo.com.cn/finalpage/2011-12-14/60321567.PDF`，本地 PDF SHA256 `bd64cbf11a24ee51aead57e4103f36f8c81f6a265c1857a363aaafb223e062e0`。隔离区严格标题解析器已改标 `needs_review`，因此它的标题区间结果不可直接晋级正式。已认证的该股 26 个旧目标行均在 2011-12-15 前，不影响 250 行最小下界。
- `600080` 的 2008-06-05 《撤销退市风险警示公告》同样只是 `*ST 金花`→`ST 金花`，自 2008-06-06 生效；2010-04-26 下一份公告正文仍写明此前简称为 `ST 金花`，然后于 04-27 升回 `*ST`。这证明 2010-01-14 至 04-22 另外 8 个旧目标日仍应排除。2008 PDF `https://static.cninfo.com.cn/finalpage/2008-06-05/40271256.PDF`，SHA256 `5cb797e7bf1d8182a1a5dbe45f2a88a5efc264ca3cde5a9ecac35a5747192579`。加上这 8 行，当前可证下界为 250 行。
- 任何没有有效进入段的 `exit` 都被反推为自首个价格日 ST；公告披露日直接当实际生效交易日，且 `build_st_status_series` 对 `end` 使用闭区间。2010-04-26 的 `600080` PDF 明示 2010-04-27 才实施；2012-06-11 的撤销 PDF 明示 06-12 才摘帽。

建议将历史事件规范为 `{symbol, announcement_id, source_url, announcement_time, action, effective_trade_date, former_name, new_name, evidence_sha256, review_status}`，其中 `action` 至少有 `entry`、`exit`、`remain_st`、`context`、`unknown`。公告标题仅作发现线索；进入/退出采用官方正文或交易所带生效日期的历史名称。区间使用 `[entry_effective_trade_date, exit_effective_trade_date)`。首个可见事件若是退出，且缺少期初历史简称或之前进入证据，记 `unknown_initial`，在正式认证中 fail-closed，不能擅自反推整段，也不能默认为非 ST。公告检索与正文缺失、分页不全、相互矛盾亦 fail-closed。

## 正式迁移边界

- `st_notice_policy_version` 和证券元数据 fingerprint 都需递增，重新构建完整候选池、代理和 v2.0/v2.3/v2.5。不能直接编辑现有 JSON、只删错成员或只重算 NAV。
- 旧 1185 目标股中，170 只有 `notice_count>0`（9095 个旧目标行），128 只缓存区间含 `cninfo_notice`（6981 行）；旧元数据没有逐条公告标题。另有 251 只价与股本已在隔离区的退市候选。全 1436 候选需要完成官方公告、历史简称、正文有效日与公告来源的对账，并解决价格/公司行为缺口，之后才有可提交的精确哈希迁移报告。
- 当前可核的最小目标名单错误见 `certified_st_target_lower_bound.csv`：236 行由 25 份入口、8 份后续状态公告的官方 PDF 有效日期证明；8 行由 `600080` 的 2008 降级与 2010 再升级公告合证；6 行由 `000010` 的 2007 仅撤销退市风险但继续其他特别处理、2013 完全退出两份官方 PDF 证明，深交所历史更名缓存辅助交叉核对。共 250 行，只说明旧目标名单违反历史 ST 排除，不推断有效成交或净值影响。

## 必要反例验收

- `S ST华新`、`S*ST华新`、`G*ST三木`、普通 `ST` / `*ST` 均识别；正常简称与退市简称分别走原门槛。
- `600080` 2010-05-06 从候选池剔除，公告日 2010-04-26 与实际生效日 04-27 分开；`000010` 2010 年六个目标日因 `S ST` 剔除；`002207` 2011—2013 不因 2020 年“申请撤销”反推为 ST。

- 对 `600180` 的“撤销退市风险警示”标题采用正文优先：2011-12-15 从 `*ST` 改 `ST` 后仍维持排除；不能以标题 `撤销` 自动结束 ST 区间。
- 全 1436 候选中任一证券缺期初状态或生效日证据时，不输出认证后的全历史绩效。之后核旧/新目标与有效持仓、成本、收益、股本及公司行为的逐日差异，并按项目既有精确哈希迁移审批与整组刷新门槛执行。
