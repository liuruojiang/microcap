# 三版共用 ST 历史解析修复（2026-10-29）

## 当前边界

用户已授权修复 v2.0、v2.3、v2.5 共用的 ST 历史解析问题。此修复不改变三版动量参数、成本参数或 v2.3 已批准的取消波动率约束。三版实际引用同一个内嵌频率模块；本次同时修复独立研究入口与内嵌正式入口。

## 已修复的问题

- 仅凭“撤销退市风险警示”的标题，无法断定其他风险也已撤销。600180 的 2011-12-14 原公告明确仍实施其他特别处理；直到 2012-08-31 公告才撤销其他风险。现在按经审阅的原文动作保持连续 ST。
- 000677 的 2016-03-24 原公告已批准退出；合并名称变更的既有 inclusive 口径后，旧 2015 年区间结束于 2016-03-25，与 2026-04-30 重新进入分离，不再错误延续至今。
- “将被实施”、问询和第三方主体标题不能独立证明本发行人的有效状态。无正文认证时明确阻断；已核实决议的未来生效公告沿用现有公告日排除口径，不擅改为生效日。
- 同日相反状态、公告主体错配、同一公告 ID 内容冲突、已认证公告缺失或原件哈希不符均明确失败，不能被普通网络失败处理吞掉后复用旧历史。
- 旧解析器与此前修复曾共用 v3 政策标识。新 metadata 增加独立解析器修订标识及正文证据指纹；存在历史 ST 的旧记录缺少这些证明时拒绝静默复用。

## 原件绑定与可复现性

`data/st_notice_evidence/registry.json` 保存经人工源审查的事件、公告 ID、主体、原题、公告日期、实际生效日（仅用于解释）、风险类别动作、原文 URL 与 SHA256。10 份发行人原始 PDF 随代码保存。`scripts/st_notice_evidence.py` 对原始字节及实时公告身份逐项验证，不从未经核实的正文自动猜事件。

真实巨潮接口已确认 600180、002193、002198、002514 的公告身份；000677 的完整真实公告列表在独立构建中验证。13 只审查对象全部成功生成新候选并通过来源版本读取；正式及原隔离 metadata 字节均未改变。完整证据位于本地 `research_reports/20261029_st_history_repair/`，其中包含来源报告、逐日 ST 对照、原件及精确文件哈希。

原件及认证模块已纳入代码一致性与整组输入哈希、云端状态运输。PDF/registry 保持字节精确，不进行换行归一化；篡改原件的恢复测试会在替换本地文件前失败。

## 正式历史重放限制
