# 2026-08-20 Top100 名单混入 ST 股票事件复盘

## 结论与影响

此前交付的 100 只名单不合格，必须撤回。名单中有 19 只当前名称为 ST 或 *ST 的股票，违反“当前名单不得包含 ST、*ST、PT”的基本约束。本次问题不是展示错误，而是筛选链路与交付验证同时失守。后续全历史审计进一步确认旧 v2.0 历史回测也受到影响，旧历史结果不再作为正式依据。

## 直接原因

1. `current_st.csv` 的快照停留在 2026-05-06，之后新增的风险警示股票不在代码排除表内。
2. 原实时名称校验只拒绝空名称和退市名称，没有把 ST、*ST、PT 作为实时名单的硬排除项。
3. 名单缓存的版本指纹没有包含“当前 ST 名称过滤规则”，旧缓存可以在规则变化后继续被读取。
4. 输出 CSV 和 Excel 前没有执行“ST 数量必须为 0”的硬性断言。
5. 既有测试只覆盖空名称，没有覆盖新增 ST、*ST、PT、旧名称覆盖和备用行情路径。

## 交付过程错误

在首次交付前，没有对最终 100 行进行独立的证券现名复核，也没有把“ST=0、代码唯一=100、总数=100”作为不可绕过的发布门槛。这是本次错误能够从数据层一路传递到用户侧的关键原因。

## 已实施整改

1. 将历史回测名称规则与实时名单规则分离：历史回测继续使用时点状态，实时名单统一拒绝 ST、*ST、PT，避免用当前名称污染历史回测。
2. 当前股票池同时检查 `current_st.csv`、证券主数据现名和实时行情现名；任一来源显示风险警示即排除。
3. 所有实时名单路径先用实时证券名称覆盖旧缓存名称，再执行风险警示过滤。
4. 在成员快照、静态缓存、实时缓存、基础名单 CSV 和最终实时名单处加入硬性断言；发现 1 只风险警示股票即失败，不再生成结果。
5. 更新缓存策略版本，旧规则生成的名单缓存自动失效。
6. 行情主节点失败时先切换同源备用节点，全部失败后使用腾讯全市场实时行情备用源；禁止用过期名单缓存冒充最新结果。
7. 最终交付增加新浪逐股行情的独立复核，验证当日交易日期、证券现名、ST/PT 数量和 100% 覆盖率。
8. 新增针对 ST、*ST、PT、名称回填、陈旧 ST 代码缓存、行情节点切换和腾讯备用源解析的自动化测试。

## 历史链路补充根因

1. 旧 ST 数据链路没有形成完整的“进入 ST—撤销 ST—再次进入 ST”时点区间；公告标题中确定实施、可能性语句和撤销语句没有被可靠区分。
2. 旧代理股票池的部分刷新使用了仅 156 只显式股票的近期集合，而非 4,975 只完整历史证券主表，产生历史股票池/生存者偏差风险。
3. 基础输出复用曾只检查文件是否存在，没有校验 ST 元数据内容指纹，更新后的元数据可能未触发代理指数重建。
4. 正式 v2.0 成本净值停留在 2026-08-12；旧文件存在时，刷新与历史改写保护之间缺少受审计的一次性迁移路径。

## 历史链路补充整改

1. ST 公告策略升级为 `cninfo-category-plus-entry-exit-keyword-v3`，完整刷新历史入选股票与当前 ST 并集 1,262 只；刷新失败 0、公告查询失败 0、未解析 0。
2. 当前 ST 快照只从最后一个已观察交易日开始，不再反向覆盖历史。
3. 使用 4,975 只历史证券主表重建代理指数；成员元数据内容指纹写入代理元数据并强制一致。
4. 对最终成员表逐调仓日复查 ST 区间；零违规和零旧策略元数据成为发布硬门槛。
5. 修复“文件存在即复用”的捷径，只有数据模型和元数据指纹完全匹配才允许复用。
6. v2.0 历史更正只通过一次性精确哈希迁移发布；旧正式文件、候选序列、代理元数据和改写审计任一字节变化，授权即失效。
7. 迁移完成后在无迁移参数下再次运行，历史改写保护正常通过，证明授权没有变成长期绕过。
